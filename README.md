# 我附庸的附庸 (My Vassal's Vassal)

> 一款以中世纪欧洲封建社会为背景的 2D 沙盒策略游戏。  
> 在领主、骑士、城堡与村庄构成的世界中，探索、征战、招募、经营领地，并逐步建立属于自己的势力。

## 🎮 游戏简介

**《我附庸的附庸》** 是一款受到《骑马与砍杀》启发的 2D 中世纪沙盒策略游戏。

游戏以大地图为核心，玩家将以一支小规模队伍开始自己的旅程，在动态运行的世界中与领主、家族、村庄、城镇及其他势力互动。通过招募士兵、参与战斗、经营经济、获取领地、管理俘虏以及参与政治关系，逐步从一个游荡者成长为拥有领土与军队的领主。

世界并非只围绕玩家运行。NPC领主、商队、巡逻队与其他势力也会独立行动、发生冲突、争夺资源，构成一个持续演化的中世纪世界。

## ⚔️ 核心玩法

- **自由探索的世界地图**：在由村庄、城镇、城堡和各类势力构成的世界中自由行动。
- **动态世界模拟**：NPC队伍拥有独立的行为逻辑，包括巡逻、贸易、移动、追击和战斗。
- **即时战斗**：进入独立的小型战场，参与士兵之间的战斗，玩家可直接操控角色。
- **军队管理**：招募士兵、雇佣佣兵、管理装备、马匹、俘虏与队伍组成。
- **封建领地体系**：与家族、领主及领地互动，逐步获得村庄、城堡等资产。
- **经济与贸易**：通过市场交易、领地收益和队伍管理构建经济体系。
- **动态政治与势力关系**：世界中的家族、领主和势力拥有各自的关系与行动。
- **成长与扩张**：从独立的小队逐步发展成为拥有军队、领地和政治影响力的势力。

## 🌍 游戏世界

游戏采用 2D 大地图与独立战斗场景相结合的结构。

| 世界地图 | 战斗场景 |
| --- | --- |
| 玩家及 NPC 队伍在地图上移动 | 独立的小型战场 |
| 村庄、城堡、城镇等地点 | 士兵自主战斗 |
| 世界时间持续推进 | 玩家直接控制角色 |
| NPC 行为与世界事件模拟 | 战斗结算与战后处理 |

大地图负责世界状态、队伍行为、经济、政治与时间推进；战斗场景负责具体的战斗表现和战斗交互。两者通过数据与系统接口进行衔接。

## 🏰 系统架构

项目采用模块化架构，尽量将数据、逻辑管理、世界模拟与表现层分离。

### 核心基础设施

- **EventBus**：系统之间的事件通信。
- **TimeManager**：统一管理世界时间与时间流速。
- **SaveManager**：负责游戏状态的存档与读取。
- **SceneManager**：负责场景切换。
- **GameManager**：管理游戏整体状态。

### 游戏数据层

通过独立的数据结构管理游戏对象，减少系统之间的直接依赖。

- UnitData：士兵与角色数据。
- PartyData：队伍数据。
- LordData：领主数据。
- SettlementData：城镇、村庄及城堡数据。
- FactionData：势力数据。

通过配置数据管理单位、装备和势力的基础属性与规则，尽量避免将游戏数值硬编码在表现或逻辑中。

### 世界模拟与管理系统

| 系统 | 职责 |
| --- | --- |
| WorldContext | 管理当前世界上下文 |
| WorldSimulation | 驱动世界模拟 |
| UnitManager | 单位数据与相关管理 |
| PartyManager | 队伍创建、管理与生命周期 |
| WorldMapManager | 大地图队伍移动及地图交互 |
| AIManager | NPC行为决策 |
| FactionManager | 势力关系与相关管理 |
| VisionManager | 世界视野相关管理 |

## 🤖 AI 辅助开发

本项目在开发过程中使用 AI 辅助编程与设计。

AI参与需求拆分、技术方案讨论、代码实现、问题排查、文档编写及迭代优化。项目仍以明确的系统架构、数据结构、功能边界和验收标准为基础，逐步推进开发。

AI 是开发工具，而非项目架构的替代品。项目通过模块化设计、明确的接口约束与分阶段开发，持续维护代码结构和系统一致性。
