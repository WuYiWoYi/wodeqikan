## 阶段 0：工程基础架构

**目标：** 项目能稳定启动，管理器职责清晰，时间统一可控，文档体系可用。

### 已完成

- [x] Godot 4.6.1 工程与目录结构
- [x] 5 个 Autoload 骨架并注册
- [x] `TimeManager` 固定步长世界 tick（0.1 秒，带卡顿保护）
- [x] `EventBus` 核心事实信号
- [x] `SceneManager` 基础场景切换
- [x] `SaveManager` JSON 存档基础接口
- [x] `GameManager` 会话状态与 `WorldContext` 创建入口
- [x] `IdGenerator` 与核心实体数据类
- [x] `WorldContext` / `WorldSimulation` 装配
- [x] `Docs/` 文档体系
- [x] 冒烟测试（时间、序列化、存档、装配）

### 剩余任务

1. 主菜单可操作：新游戏、继续、读取、退出按钮接通。
2. `WorldContext` ↔ `SaveData` 的聚合与恢复。
3. 读档流程：读取 → 校验版本 → 重建管理器与实体 → 进入大地图。
4. 启动/退出会话的完整清理（暂停原因、信号连接、场景）。
5. 最小输入映射：暂停、正常、二倍速（为阶段 1 准备）。

### 验收标准

- 启动进入主菜单无报错。
- 点击新游戏进入大地图场景，`WorldContext` 已创建。
- 返回主菜单后世界上下文被正确销毁，再次新游戏不残留旧数据。
- 存档写入 `user://saves/`，可读回并重建实体。
- 冒烟测试持续通过。

## 阶段 1：大地图基础系统

**目标：** 玩家能在大地图上移动、控制时间、与地点进行基础交互。

### 任务

1. 大地图场景背景与地图边界（`WorldMapManager.world_bounds`）。
2. 玩家部队数据与旗帜图标。
3. 点击地面设置目标，部队按世界 tick 移动。
4. 图标表现：读取数据并平滑插值，不写回数据。
5. 时间控制 UI：暂停、正常、二倍速，绑定 `TimeManager`。
6. 地点数据（村庄/城镇/城堡）与地图标记。
7. 到达地点后打开左侧交互面板；初期只有“离开”。
8. 面板打开时压入暂停原因，关闭时移除。

### 验收标准

- 玩家部队能在地图边界内移动，速度受时间倍率影响。
- 暂停时大地图世界完全静止，UI 动画仍运行。
- 到达地点弹出面板；离开后保持暂停，下一次操作恢复。

## 阶段 2：世界模拟系统

**目标：** 没有玩家操作时，NPC 部队也能独立运行。

### 任务

1. `WorldSimulation` 固定更新顺序。
2. 生成多个 NPC 部队并赋予简单目标。
3. `WorldMapManager` 直线移动与到达判定。
4. 视野系统：距离检测、可见集合、发现/离开。
5. 遭遇检测：部队进入战斗距离时触发事件。
6. 世界模拟与大地图表现彻底分离（大地图未加载仍能推进）。
7. 世界模拟性能基线（部队数量、每 tick 耗时）。

### 验收标准

- 玩家静止时，NPC 部队持续移动并改变位置数据。
- 关闭/不加载大地图场景时，世界 tick 仍推进。
- 视野发现与离开事件正确，不重复触发。

---

## 阶段 3：士兵与部队系统

**目标：** 能生成士兵、组成部队，并在小场景中移动和攻击。

### 任务

1. `UnitData` 与 `UnitManager` 完整化。
2. `UnitConfig` 示例数据与加载。
3. `StatCalculator`：等级基础 + 装备加成。
4. `UnitController`：移动、加减速、朝向、攻击、受击、死亡状态机。
5. 攻击流程与左右朝向。
6. 步兵部件视觉与动画。
7. 骑兵部件视觉与移动参数。
8. 横版带纵深的 Y 排序与阴影。
9. `PartyManager` 成员管理。
10. 部队管理面板（暂停世界时间）。
11. 编队数据接口（站位计算可先只实现线阵）。

### 验收标准

- 可从配置生成单位并加入玩家部队。
- 小场景中单位能移动、攻击、死亡，左右朝向正确。
- 骑兵与步兵共用控制逻辑，仅参数与视觉不同。
- 部队面板能显示成员并暂停世界时间。

## 阶段 4：基础战斗系统

**目标：** 从大地图进入战斗，完成战斗并返回大地图。

### 任务

1. `BattleSession` 完整生命周期。
2. `BattleManager.start_battle` / `finish_battle`。
3. 参战部队锁定与解锁。
4. `BattleScene` 初始化：读取会话、生成双方单位。
5. 玩家单位控制。
6. `UnitAI` 基础行为：Idle / Move / Attack / Retreat。
7. 伤害、死亡、胜负判定。
8. 战斗结算写回 `UnitData` / `PartyData`。
9. 战斗期间 WorldTime = 0.5，世界继续推进。
10. 战斗结果返回大地图。

### 验收标准

- 玩家在大地图遭遇敌军后进入战斗。
- 战斗结束后 HP、死亡、经验正确写回，部队解锁。
- 战斗期间其他 NPC 部队继续移动。
- 战斗期间不能存档。

## 阶段 5：AI 领主与世界交互

**目标：** AI 领主独立行动，玩家能与 NPC 和地点交互。

### 任务

1. `LordData` 与领主-部队关联。
2. 领主战略决策循环（招募、搜索、攻击、撤退）。
3. 部队战术决策。
4. 村庄招募流程。
5. 地点交互扩展（招募、查看驻军等占位入口）。
6. 对话数据与 `DialogueManager`。
7. 对话分支、条件、效果。
8. 大地图与小场景共用对话 UI。

### 验收标准

- 领主能在无人干预下招募、移动、避战或交战。
- 玩家可通过对话获得信息并改变状态（至少一个示例分支）。
- 对话期间时间规则符合 `Time_System.md`。

---

## 阶段 6：援军与高级战斗

**目标：** 大地图援军能动态加入正在进行的战斗。

### 任务

1. 战斗期间援军距离/阵营检测。
2. 支援条件与加入流程。
3. `BattleSession` 动态加入部队与单位生成。
4. 部队阵型：线阵、方阵、弓手线、骑兵楔形。
5. 集群命令：移动、攻击、防守、撤退。
6. 援军加入时的数据同步与表现。

### 验收标准

- 友军进入战场范围后能加入战斗。
- 敌军援军同样生效。
- 阵型切换不破坏单位 AI 与战斗结算。

```text
阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5 → 阶段 6 → 阶段 7
```

例外：阶段 3 的纯数据部分（`UnitData`、`StatCalculator`）可与阶段 2 并行，但不得跳过阶段 1 的大地图基础。

## 完成定义（DoD）

一个任务算完成，必须同时满足：

1. 代码可运行，无解析错误与新增运行时报错。
2. 有对应验收方式（冒烟测试、手动步骤或单元测试）。
3. 相关文档、`Current_Status.md` 已更新。
4. 新增接口/字段已写入对应系统文档。
5. 未引入新的全局单例或跨层直接写数据。
