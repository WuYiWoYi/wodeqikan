## D001 · 文档体系与权威来源

**日期：** 2026-11-20
**状态：** 已确定

**决策：** `Docs/` 是唯一持续维护的开发依据；`md/` 下源规划 V0.2 保持只读，作为需求来源。

**原因：** 避免两份文档同时演化产生矛盾。实现细节以 `Docs/` 为准，源规划只提供原始意图。

**影响：** 任何架构变化先更新 `Docs/`，再改代码。

## D002 · 大地图俯视 + 小场景横版带纵深

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- 大地图：俯视平面，部队在 XY 平面移动。
- 小场景：横版侧视，Y 轴表示前后纵深，单位可在 XY 平面移动，按 Y 排序。
- 攻击方向仅左右，默认朝左。

**原因：** 匹配源规划的左右攻击、部件化人体/马匹美术，同时保留阵型所需的纵深空间。纯横版会让方阵退化为一条线。

**影响：**

- 小场景单位需要 Y 排序与纵深移动。
- 大地图与战斗使用不同相机与坐标表现。

**更新（D060）：** 攻击命中已扩展为 360°定向矩形；本节“攻击方向仅左右”只描述人物贴图朝向，不代表当前命中判定。

## D003 · 静态配置 Resource、运行时 RefCounted、存档 JSON

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- 静态配置：`Resource` + `.tres`（`Data/`）。
- 运行时实体：`RefCounted` 纯数据类。
- 存档：JSON（`user://saves/`）。

**原因：**

- Resource 提供编辑器编辑、类型安全与资源引用。
- RefCounted 不进入场景树，适合大量实体与显式生命周期。
- JSON 透明、易调试、方便迁移和外部工具处理。

**影响：**

- 配置资源脚本放 `Scripts/Config/`，数据文件放 `Data/`。
- 实体类必须实现 `to_dict/from_dict`，不持有节点引用。

## D004 · WorldContext + WorldSimulation 替代 WorldManager

**日期：** 2026-11-20
**状态：** 已确定

**决策：** 源规划的 `WorldManager` 拆为：

- `WorldContext`：会话级容器，持有管理器，跨场景常驻。
- `WorldSimulation`：消费 `world_tick`，按固定顺序推进世界。

**原因：** 容器与调度职责不同；战斗/小场景期间世界仍需运行，容器必须独立于场景存在。

**影响：** 所有世界管理器由 `WorldContext` 装配，不新增 Autoload。

---

## D005 · 世界时间固定步长 0.1 秒

**日期：** 2026-11-20
**状态：** 已确定

**决策：** `TimeManager` 每 0.1 游戏秒发出一次 `world_tick`；单帧最多补 10 次，超出丢弃累积。

**原因：** 世界逻辑与渲染帧率解耦，保证 NPC 移动/AI 行为稳定可复现；卡顿保护避免死亡螺旋。

**影响：** 世界系统只订阅 tick，不在 `_process` 里实现世界逻辑。

---

## D006 · 不使用 Engine.time_scale / get_tree().paused

**日期：** 2026-11-20
**状态：** 已确定

**决策：** 游戏暂停通过 `TimeManager` 的门控与暂停原因栈实现。

**原因：**

- 全局时间缩放会同时影响 UI 动画。
- `get_tree().paused` 会冻结 UI、加载动画和部分管理器。
- 世界模拟需要固定步长，而不是全局 delta 缩放。

**影响：** 所有需要暂停的功能必须使用 `push_pause/pop_pause`。

---

## D007 · 暂停原因栈

**日期：** 2026-11-20
**状态：** 已确定

**决策：** `TimeManager` 维护暂停原因集合，任一原因存在即暂停。

**原因：** 多个系统（面板、对话、小场景）可能同时要求暂停，布尔值会互相覆盖。

**影响：** 压入与移除必须成对；原因常量集中在 `TimeManager`。

## D008 · 战斗期间 WorldTime = 0.5

**日期：** 2026-11-20
**状态：** 已过时（屏幕内战斗由 D028 替代；离屏战斗由 D079 替代）

**更新（D079）：** 离屏 AI 对 AI 战斗保持世界正常倍率，每游戏小时结算一次，不再使用 0.5 倍速覆盖。

## D011 · ID 格式与计数器

**日期：** 2026-11-20
**状态：** 已确定

**决策：** `<PREFIX>_<6 位序号>`，由 `IdGenerator` 生成，计数器随存档保存，永不复用。

**原因：** 稳定引用实体；避免节点名/数组下标变化导致存档失效。

**影响：** 读档必须先恢复计数器；实体跨部队转移时 ID 不变。

## D021 · 地点交互由大地图场景控制器检测

**日期：** 2026-11-20（2026-11-22 修订）
**状态：** 已修订

**决策：**

- 地点交互入口仍放在 `world_map.gd`，不放进 `WorldMapManager`。
- 鼠标左键点击地点（判定半径 45 像素）只表达“前往该地点”：记录 `_pending_settlement_interaction_id`，通过 `WorldMapManager.set_party_target()` 设置移动目标，并把基础倍率切回 1x。
- 点击时若玩家已处于地点交互半径 40 像素内，允许直接打开面板；否则必须等待真正到达。
- 到达检测在 `_process()` 中执行：pending 非空、地点仍存在、玩家可用、移动已停止、玩家与地点距离 ≤ 40、且当前移动目标仍指向该地点时，才消费 pending 并调用 `_open_settlement()`。
- 只有 `_open_settlement()` 负责停止部队、设置基础倍率为 0、压入 `ui_panel` 暂停并显示面板。
- 普通移动、追逐、跟随或路过地点不会创建 pending，也不会自动打开面板。
- 点击普通地图位置、点击部队、切换地点目标、外部停止、进入战斗或离开大地图时清除 pending。

**原因：** “点击地点”代表意图，“到达地点”才是交互条件；把两者分离可避免远距离点击直接暂停世界，也保留“路过不打扰”的既有规则。

**影响：** 地点交互目前不能在无大地图场景时发生；pending 是运行时状态，不进入存档。未来遭遇/战斗检测仍应放在世界模拟层。

## D024 · 实体注册、删除与成员转移的安全规则

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- `UnitManager.add_unit()` / `PartyManager.add_party()` 遇到已存在 ID 时拒绝注册，返回空字符串并 `push_error`，原实体不变。
- `UnitManager.remove_unit()` 拒绝删除 `current_party_id` 非空的单位，必须先经 `PartyManager.remove_member()`。
- `PartyManager.add_member()` 是转队的唯一入口：先完成部队/单位存在性与阵营校验，再从所有其他部队成员列表移除，最后加入目标部队并更新 `current_party_id`。
- 重复加入同一部队不重复写入；同一部队成员列表中的重复项会被归一化为一条。
- 本阶段要求单位与部队 `faction_id` 相等，跨阵营加入直接拒绝。
- `remove_party()` 清空所有指向该部队的 `current_party_id`，单位保留在 `UnitManager`。

**原因：** 保持“一个单位最多属于一支部队”和双向归属一致；避免重复 ID 静默覆盖与删除单位后留下悬空成员引用。

**影响：** 删除单位必须先处理归属；跨阵营招募需要未来新增专门接口，不能绕过 `add_member()`；`remove_unit` / `remove_party` 改为返回 `bool`。

## D025 · 读档后校验士兵-部队成员关系

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- `PartyManager.validate_membership_consistency()` 返回错误描述列表，检查：
  1. 每个成员 ID 都有对应 `UnitData`；
  2. 每个非空 `current_party_id` 都有对应 `PartyData`；
  3. 一个单位最多出现在一支部队的成员列表中；
  4. `current_party_id` 与所在部队成员列表双向一致（含同一列表内重复项）。
- `WorldContext.load_from_save_data()` 在两个仓储恢复完成后调用校验；失败时逐条 `push_error` 并返回 `false`。
- 本阶段不自动修复：无法确定原始数据意图时，保留读入状态并拒绝进入游戏，避免擅自改写存档。

**原因：** 两个管理器各自反序列化成功，不代表跨实体引用正确；静默修复可能掩盖存档损坏。

**影响：** 损坏成员关系的存档无法加载，需要后续显式迁移/修复工具；其他实体引用（阵营、地点、领主）尚未纳入同一校验入口。

## D026 · StatCalculator 作为属性初始化的唯一入口

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- `UnitManager.create_unit()` 只负责身份、配置引用、阵营、装备与注册；基础属性统一调用 `StatCalculator.apply_to_unit()`。
- 当前 `compute_final_stats()` 直接复制 `UnitConfig` 的 `base_max_hp` / `base_attack` / `attack_interval` / `move_speed` / `attack_range`。
- `apply_to_unit()` 写入属性缓存并只对 `current_hp` 做上限 clamp；出生满血由 `UnitManager` 显式设置。
- 等级成长与装备加成暂不实现，接口参数保留。

**原因：** 避免 `UnitManager` 与 `StatCalculator` 各维护一套属性规则，导致后续成长/装备系统接入时出现两套真实来源。

**影响：** 所有运行时属性重算必须经过 `StatCalculator`；新增属性先扩展该接口，再接入调用方。

## D027 · 战斗会话、场景与结算职责分离

**日期：** 2026-11-20
**状态：** 已确定

**决策：**

- `BattleManager.start_battle()` 只创建 `BattleSession`、校验部队、生成 `BattleUnitState`、锁定参战部队并压入战斗暂停；不切换场景。
- 大地图交互控制器创建会话后调用 `SceneManager` 进入 `BattleScene`。
- `BattleScene` 读取会话生成 `UnitActor`，逐帧驱动 `UnitController`；伤害只写 `BattleUnitState.battle_hp`，不修改 `UnitData` / `PartyData`。

## D040 · 新增 EncounterManager，区分强制遭遇与玩家中途参战

**日期：** 2026-11-21
**状态：** 已确定

**决策：**

- 新增 `EncounterManager`，集中负责：
  - AI 对 AI / AI 对玩家的攻击意图遭遇（`AI_ENCOUNTER_RADIUS = 50`）；
  - 玩家接近进行中的离屏战斗时的中途参战交互（`BATTLE_INTERACTION_RADIUS = 55`）；
  - 停止相关部队、清理追逐/攻击意图、委托 `BattleManager` 创建或加入战斗。
- `WorldMapManager` 保留移动、跟随与边界职责；不再直接判定遭遇。
- `WorldSimulation` 顺序：移动 → 遭遇检测 → 玩家中途参战检测 → AI；存在待处理交互时跳过该 tick 的 AI。
- 两种玩家交互明确区分：
  - 敌对 AI 主动攻击玩家：`encounter_dialogue`（**更新：D080 增加“撤退”与玩家主动追击接触**）；
  - 玩家接近已发生的 NPC 战斗：`battle_encounter_dialogue`，提供“加入战斗/离开”。
- 玩家选择离开后，`EncounterManager` 记录 declined battle id；玩家仍在 90 世界单位退出范围内时不重复提示，离开范围后可重新触发。
- 玩家加入使用 `BattleManager.try_join_battle()`，加入已有 BattleSession，不创建新战斗；战斗转换为屏幕战斗。
- 战斗结束、ID 变化、玩家已参战或面板异常关闭时，WorldMap 清理本次交互暂停与待处理请求。
- 不改变存档 Schema；攻击意图、待处理遭遇、交互 ID 与拒绝记录均为运行时状态。

## D041 · 玩家角色是普通 Unit，控制权与身份分离

## D048 · 骑乘属性由 StatCalculator 统一计算

## D062 · 玩家攻击动作与命中判定解耦（自由攻击）

**日期：** 2026-11-21
**状态：** 已确定

**决策：**

- 玩家左键始终先读取鼠标世界坐标并确定 360°攻击方向。
- 冷却结束时，无论该方向矩形内是否有敌人，都播放完整长矛动画并进入 `attack_interval` 冷却。

## D104 · 箭矢分离地面投影与视觉高度

**日期：** 2026-11-21
**状态：** 已确定

**决策：**

- `ArrowProjectile` 节点自身 `position` 永远是地面投影，参与 `Characters` 的 YSort。
- 视觉 Sprite 作为子节点，只按当前高度偏移 `(0, -h)`；高度不写入 `position`，不影响排序。
- 地面位置线性插值 `P(t) = P0 + (P1 - P0)t`；高度 `h(t) = launch_height(1-t) + 4·arc·t(1-t)`。
- 箭矢 `z_index = UnitActor.ACTOR_Z_INDEX`，与人物共用同一深度层。

**原因：** 如果直接把高度加到节点坐标，箭矢会被 YSort 误判为更远处/更近处，并破坏现有“脚底坐标排序”规则。

**影响：** 高空箭矢仍按地面位置与人物前后排序；未来若需要真正的高空遮挡层，必须单独引入，不能改 `position` 语义。

**状态：** 已确定

## D166 · 角色整体动态排序由战斗场景写入 z 波段，CanvasGroup 方案废弃

**日期：** 2026-11-26
**状态：** 已确定

**决策：**

- 角色之间的前后关系以完整角色为单位：`BattleScene` 在 `_physics_process` 中收集 `World/Characters` 下全部 `UnitActor`（含尸体），按权威 `BattleUnitState.battle_position.y` 升序排名；相同 Y 使用稳定节点名打破平局。

- 尸体不在 `_actors` / 控制器集合中，但仍是 `Characters` 的子节点，因此继续参与每帧排序；死亡时冻结位置，倒地与淡出不改变名次。

- `CanvasGroup` 方案废弃：实测其子节点仍按各自 z 进入全局 z 分层，不能把整个角色合成为同一个排序单位。

**原因：** 画布 z_index 是全局排序键，同一角色内部相对 z 不同会使不同角色的部件交错；YSort 只对相同 z 的节点按 Y 排序，无法覆盖这种交错。角色级 z 波段在不改动内部层级和动画结构的前提下，保证前排最低部件仍高于后排最高部件。

**影响：** 排序逻辑集中在 `BattleScene` 与 `UnitActor`，所有表现状态（攻击、受击、僵直、倒地、尸体留存与淡出）共用同一规则；同屏角色超过 55 时需压缩内部层级跨度或拆分绘制。窗口像素探针 `Tests/_debug/sort_probe.tscn` 验证真实骑乘/步兵模型无跨角色穿插。

## D172 · 部队旗帜遮罩改用局部像素正圆；修复 AtlasTexture 图集 UV 导致的椭圆失真

**日期：** 2026-11-27
**状态：** 已确定

**决策：**

- 根因不是圆形底盘或描边被非等比缩放，而是旗帜遮罩 shader 对 `UV` 的假设错误：`TextureRegion.get_trimmed_texture()` 返回 `AtlasTexture`，canvas shader 的 `UV` 是整张图集的归一化坐标（实测 48×48 图集中 30×36 有效区域对应 u≈0.188–0.813、v≈0.125–0.875），并非有效贴图的 0–1。旧代码按 `UV - 0.5` 计算遮罩，使遮罩实际变成约 52×43 世界像素的椭圆：既覆盖黑色描边，又溢出 36 像素圆形标记。
- `map_flag_circle.gdshader` 新增 `use_local_circle` 模式：`vertex()` 通过 `varying vec2 local_position` 传递画布局部像素坐标，`fragment()` 按 `circle_center` 与 `circle_radius` 裁剪。该模式与 `AtlasTexture`、旗帜宽高比、图集区域均无关。
- `PartyIcon` 使用该模式：`circle_center = (0, 0)`，`circle_radius = get_flag_clip_radius() / flag_sprite.scale.x`；精灵等比缩放后，可见世界半径严格等于黑色描边内缘（16.25）。主体、黑色描边、玩家外圈、白色悬浮描边与旗帜遮罩因此共用 `PartyIcon` 的同一局部坐标系与圆心。
- 不修改 `marker_radius`、`border_width`、`flag_max_size`、点击/悬浮半径或交互逻辑；不改变地图缩放实现（`_set_camera_zoom()` 始终保持 `Vector2(z, z)`）。
- shader 默认仍为旧 UV 模式，地点家族徽章的既有调用不受影响；该处的同类问题记录为 KI546，留待单独评估。

**原因：** 圆形失真来自遮罩坐标系与主体坐标系不一致，而不是尺寸参数。把遮罩改到主体相同的局部像素空间可以从根上保证正圆、同心，并消除对贴图裁剪方式（AtlasTexture）与宽高比的隐式依赖。

**影响：** `Shaders/map_flag_circle.gdshader`、`party_icon.gd`、`party_marker_style.gd`（移除仅供旧 UV 模式使用的 `get_flag_clip_uv_radius()`）与 `stage13_world_map_ui_test` 同步；窗口化探针实测 0.5x/1x/2x 黑色描边包围盒分别为 18×18、38×38、76×76，旗帜/描边/白色悬浮描边均保持正圆且同心。存档、移动、AI 与建筑标记未修改。
